# Telegram-бот для записи клиентов студий красоты — спецификация MVP

## Executive Summary
Telegram-бот, который заменяет CRM для небольших студий красоты и частных мастеров без существующей системы записи. Бот сам ведёт диалог с клиентом, показывает свободное время мастеров, записывает, присылает напоминания и позволяет отменить/перенести визит. Мастера платят ежемесячную подписку за использование.

## Проблема
Небольшие студии и частные мастера (маникюр, брови, стрижки и т.п.) сегодня ведут запись вручную — в блокноте, Excel или по телефону. Это приводит к:
- потерянным заявкам вне рабочего времени мастера;
- неявкам клиентов из-за отсутствия напоминаний;
- ручной рутине при переносах/отменах записи.

Существующие системы (YCLIENTS, Altegio, DIKIDI) избыточны и дороги для одного мастера или маленькой студии, требуют внедрения отдельной CRM. Ниша: бот, который сам ЯВЛЯЕТСЯ и точкой контакта с клиентом, и системой учёта записей — не требует установки ничего дополнительного.

## Позиционирование
Не прямой конкурент крупным CRM-системам. Целевой сегмент — мастера и небольшие студии (2–10 человек), у которых **нет** системы записи вообще. Ключевое УТП: заменяет и админа, и CRM, дёшево и без внедрения.

## Success Criteria (для MVP)
- Первые платящие студии (цель: 5–20 в первые 3–6 месяцев) — валидация готовности платить.
- Retention: мастера продолжают пользоваться ботом после пробного периода.
- Снижение неявок клиентов за счёт напоминаний (качественная метрика со слов мастеров на раннем этапе).
- Долгосрочная цель (за пределами MVP): рост в крупный продукт либо продажа бизнеса — при низкой цене подписки (300–700 ₽/мес) и платном привлечении через рекламу это потребует пересмотра unit-экономики (см. риски).

## Пользователи (роли)
1. **Клиент студии** — конечный пользователь, пишет боту, записывается на услугу. Низкий технический уровень, ожидает простоты (кнопки).
2. **Мастер / сотрудник студии** — сам ведёт свой график, услуги и цены через веб-панель. Может не быть технически подкован.
3. **Владелец студии** (в MVP не выделен отдельной ролью с особыми правами — см. "Вне рамок MVP") — просто один из мастеров студии, пригласивший остальных.
4. **Founder/оператор SaaS** (вы) — управляет тарифами, следит за платежами, поддержкой.

## Пользовательский путь

### Клиент записывается на услугу
1. Клиент открывает Telegram-бот (по ссылке от студии/из рекламы студии).
2. Бот показывает список студий/мастеров, к которым у клиента есть доступ (либо сразу открывается на конкретной студии по deep-link).
3. Клиент выбирает мастера → выбирает услугу (кнопки) → видит доступные слоты времени → выбирает слот.
4. Бот запрашивает имя и телефон (если это первое обращение клиента), запрашивает согласие на обработку персональных данных (см. Security).
5. Бот подтверждает запись, показывает итог (мастер, услуга, дата/время, адрес).
6. За N часов до визита бот присылает автоматическое напоминание с кнопками «Подтвердить» / «Отменить» / «Перенести».
7. Клиент в любой момент может открыть «Мои записи» в боте и отменить/перенести предстоящую запись.

### Мастер настраивает профиль
1. Мастер регистрируется в веб-панели (email/телефон + пароль, либо вход через Telegram).
2. Создаёт/присоединяется к студии.
3. Настраивает: рабочие часы, список услуг (название, длительность, цена), правила напоминаний.
4. Получает ссылку на бота, которую даёт клиентам (или клиент находит студию через общий каталог в боте — решить при дизайне).
5. Видит список своих записей на текущую/будущую дату (в веб-панели; в MVP бот — только для клиентов, не для управления мастером).
6. Оплачивает подписку после окончания пробного периода (14 дней) через автосписание ЮKassa.

## Функциональные требования

### Must Have (P0)
- Регистрация мастера в веб-панели, создание студии.
- Настройка мастером: рабочее расписание, услуги (название/цена/длительность).
- Присоединение нескольких мастеров к одной студии, каждый ведёт свой график независимо.
- Клиентский сценарий записи в Telegram-боте (кнопки/меню): выбор студии → мастера → услуги → времени → подтверждение.
- Хранение карточки клиента (имя, телефон, Telegram ID) при первой записи, повторное использование при следующих обращениях.
- Автоматическое напоминание клиенту перед визитом (за 24ч и/или 2ч — уточнить при разработке).
- Отмена и перенос записи клиентом через бота.
- Подписка на сервис: пробный период 14 дней, далее автосписание через ЮKassa (или аналог), ежемесячный тариф ≈300–700 ₽ за мастера/студию (модель тарификации — за студию или за мастера — уточнить при биллинге).
- Явное согласие клиента на обработку персональных данных при первом обращении к боту (152-ФЗ).

### Should Have (P1)
- Уведомление мастеру в Telegram о новой записи/отмене.
- Повторная запись в один клик («записаться как в прошлый раз»).
- Простая аналитика для мастера в веб-панели (кол-во записей, отмен, доход по услугам — без интеграции реальных платежей, т.к. оплата офлайн).
- Каталог/поиск студий внутри бота (если распространение идёт не только по прямым ссылкам).

### Nice to Have (P2)
- WhatsApp/Instagram каналы (после проверки Telegram MVP).
- Предоплата/депозит через бота при записи.
- AI-понимание свободного текста как альтернатива кнопкам.
- Роли доступа внутри студии (владелец видит всех мастеров, мастер — только себя).
- SMS-напоминания как резервный канал, если клиент не открывает Telegram.

## Модель данных (ключевые сущности)
- **Studio** — id, название, адрес, список мастеров.
- **Master** — id, studio_id, имя, рабочие часы, услуги, статус подписки/оплаты.
- **Service** — id, master_id, название, длительность, цена.
- **Client** — id, telegram_id, имя, телефон, согласие на обработку ПДн (дата/факт).
- **Booking** — id, client_id, master_id, service_id, дата/время, статус (подтверждена/отменена/перенесена/завершена).
- **Subscription** — master_id (или studio_id), тариф, статус оплаты, дата следующего списания.

Открытый вопрос: подписка привязана к студии в целом или к каждому мастеру отдельно — нужно решить до реализации биллинга, т.к. напрямую влияет на цену для студий с несколькими мастерами.

## Техническая архитектура
- **Telegram-бот**: один общий бот (Telegram Bot API) на все студии — клиент выбирает студию/мастера внутри диалога, а не через отдельные боты. Взаимодействие — кнопки/inline-меню (не свободный текст/AI в MVP).
- **Веб-панель администрирования**: отдельное веб-приложение для мастеров — управление расписанием, услугами, ценами.
- **Backend**: единый сервис с мультитенантной моделью данных (один бот и одна БД обслуживают все студии).
- **Платежи (подписка мастеров)**: интеграция с ЮKassa (или аналогом) для автоматического ежемесячного списания.
- **Оплата услуг клиентом**: вне бота, на месте у мастера — интеграция не требуется в MVP.
- Рекомендация по стеку (т.к. соло-разработка и важна скорость MVP): Node.js (Telegraf/grammY) или Python (aiogram) для бота + любой привычный веб-фреймворк для админ-панели; хостинг — простой VPS или PaaS (Railway/Render) для старта, без необходимости в сложной инфраструктуре при текущем масштабе.

## Нефункциональные требования
- **Производительность**: не критично на старте (десятки-сотни студий), стандартный отклик бота <2 сек.
- **Надёжность**: напоминания должны отправляться надёжно (retry при сбое) — это ключевая ценность продукта, нельзя терять.
- **Безопасность/данные**: хранение ФИО и телефона клиентов — персональные данные, требуется согласие при сборе (152-ФЗ), ограничение доступа мастера только к своим клиентам/студии.
- **Изоляция данных**: мастер не должен видеть записи и клиентов других студий.

## Вне рамок MVP
- WhatsApp, Instagram, веб-виджет как каналы общения с клиентом (только Telegram в MVP).
- Предоплата/депозит в боте.
- AI-диалог на свободном тексте.
- Отдельная роль «владелец студии» с правами над другими мастерами (в MVP все мастера равноправны внутри студии).
- Каталог студий для холодного поиска клиентами (если распространение идёт по прямым ссылкам от студий).

## Риски и открытые вопросы
1. **Unit-экономика**: цена 300–700 ₽/мес при платном привлечении через таргетированную рекламу может не покрывать CAC на старте. Рекомендация: считать CAC на первых 10–20 клиентах до масштабирования бюджета на рекламу; рассмотреть более дорогой тариф для студий с несколькими мастерами.
2. **Легальная сторона приёма платежей**: для регулярного приёма подписки от мастеров через автосписание потребуется оформление (ИП/самозанятость) — уточнить до запуска биллинга.
3. **Тарификация студий с несколькими мастерами**: платит студия целиком или каждый мастер отдельно — влияет и на цену, и на модель данных подписки.
4. **Распространение бота клиентам**: не проработан сценарий, как клиент впервые попадает в бот (deep-link от студии, QR-код в салоне, реклама студии) — нужно решить при дизайне онбординга.
5. **Конкуренция с рекламой в социальных сетях**: конверсия таргетолога в оплаченную подписку не гарантирована — стоит проверить органическими каналами (сообщества мастеров) параллельно с платным трафиком.

## Приложение: контекст обсуждения
- Позиционирование выбрано как «бот = CRM для малых и частных мастеров», а не «AI-диалог вместо кнопок» — важно не путать с более сложным AI-ассистентом при дальнейшем планировании.
- Каждый мастер студии сам ведёт свой график (не только владелец студии) — сознательное решение, увеличивающее сложность MVP по сравнению с рекомендованным упрощённым вариантом, но соответствующее модели работы студий с «арендой кресла».
