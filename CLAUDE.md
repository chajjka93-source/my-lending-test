# Правила для AI-агента

## Постоянное правило

После каждого изменения кода обновляй соответствующую документацию (README, ARCHITECTURE, CHANGELOG, .env.example). Документация всегда должна соответствовать коду.

Перед завершением задачи проверь затронутые документы. Запуск и возможности описывай в README, устройство и данные — в ARCHITECTURE, историю — в CHANGELOG, реально используемые настройки — в .env.example. Не меняй не затронутые разделы и не придумывай ключи.

Обе формы только формируют текст; копирование использует Clipboard API с ручным выделением текста при отказе. На первом экране справа — карточки услуг со ссылками на `#pricing`; пример чата помощника удалён, подключения к ИИ нет. Демо Direct Reports — внешняя ссылка, исходники приложения не входят в рабочий код лендинга.

При проверке истории отделяй `git diff` от изменений текущей сессии: diff показывает все незакоммиченные изменения относительно HEAD. На 11 октября 2026 года локальный HEAD — `6c38cec`, ветка `main`; редизайн уже находился в рабочей папке до этой сессии. В этой сессии проверяли сайт, сохраняли скриншоты и обновляли документацию; коммит, push и публикация не выполнялись. Временные профили `.browser-check/` и `.browser-check-edge/` не являются исходниками сайта и не должны попадать в коммит или публикацию.

## Правила изменений

1. Читай код перед правками. Не добавляй React, npm-зависимости, сборщик или сервер ради текста и CSS.
2. Сохраняй ID, используемые скриптами и якорями. При переименовании обновляй все ссылки и обработчики.
3. Учитывай каскад CSS и поздние переопределения. Проверяй обе темы и мобильную версию.
4. Формы только готовят текст. Не показывай «отправлено», пока реальной отправки нет. Пользователь сам отправляет сообщение в Telegram.
5. При изменении обработки данных обновляй privacy.html. Сейчас ни тема, ни ответы не сохраняются в localStorage.
6. Сохраняй реальные контакты, цены, статусы и изображения, если задача не требует их изменения. Не выдумывай отзывы, сертификаты и результаты.
7. Сохраняй читаемый текст, видимый фокус, подписи и ошибки полей, inert для закрытого меню, Escape и prefers-reduced-motion.
8. Не добавляй секреты в HTML, CSS, документы или конфигурацию Git. Сейчас .env.example содержит только комментарии: код не читает переменные окружения.
9. Не утверждай, что push или публикация прошли, без успешного результата. У GitHub и Sites разные процессы публикации; настройки Vercel не подтверждены кодом.
10. Не заменяй историю GitHub историей Sites, не применяй force push, сохраняй пользовательские изменения вне задачи.

## Проверки

Из корня репозитория выполни `node verify.cjs` и `git diff --check`. Для документации проверь ссылки, команды и соответствие коду. Для интерфейса проверь обе темы, телефон, Tab, Escape, квиз, форму, копирование и FAQ.

`verify.cjs` проверяет синтаксис встроенных скриптов, дубли ID и якоря, выводит наличие `premium.css`. Значение `css: false` само по себе не меняет код завершения; проверяй вывод.

`browser-review.cjs` требует уже запущенного Chromium-браузера с CDP на `127.0.0.1:9333`, отдельным профилем и хотя бы одной вкладкой; Node.js должен поддерживать встроенные `fetch` и `WebSocket`. Скрипт использует жёсткий URL `file:///C:/Users/Марина/Documents/Projects/my-lending-test/index.html`, несмотря на неиспользуемые импорты `path` и `pathToFileURL`. Не описывай путь как относительный; соответствующая фраза в `docs/TECHNICAL.md` устарела.

Скрипт сохраняет `preview-desktop.png` и `preview-mobile.png` для ширин 1440 и 390 px, выводит ширину страницы и проверяет меню, Escape, FAQ, подготовку сообщения и возврат к контактной форме. Темы, квиз, ошибки полей, копирование, Tab, изображения и ошибки браузерной консоли нужно проверять отдельно. Не называй запуск полной проверкой интерфейса: оценивай значения в выводе, поскольку неуспешное взаимодействие (`false`) не устанавливает ненулевой код завершения. В этой сессии автоматическое копирование не подтверждено; проверен ручной режим.

Для просмотра пользователем давай абсолютные кликабельные ссылки на реальные локальные файлы. Скриншот показывает сохранённый вид; для проверки кнопок нужно открыть `index.html` в браузере.

В конце сообщи, что изменено, какие проверки прошли и что осталось непроверенным.
